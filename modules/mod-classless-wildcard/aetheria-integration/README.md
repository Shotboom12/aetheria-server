## Things a live install MUST get right

* **Creature displays**: `cw_coa_creatures_displays.sql` must not overwrite display/model ids 200000-200013 (the owner's own Retail
  displays). The CoA recolours land on 977364+; `creature_model_info` rows for them are required or the creatures (for example
  the Necromancer Abomination) load without a model and are invisible: use
  `data/sql/db-world/cw_coa_creatures_model_info.sql`, `..._pending.sql` and `..._derived.sql`. All creature_model_info rows in
  `coa-core-input/data/sql/updates/pending_db_world` are needed, not only the migrations staged earlier.
* **Kalibros' globally class-changing SQL** (class loot, quests, item classes) stays excluded: the Hero is the only class that
  changes; Classic classes must stay untouched.
* **Client archives load alphabetically (last wins) in this client**, not "locale patches above base". The variants archive
  (`client-patch/build_variants_patch.py`) reads in that order; reading in Kalibros' default order would silently drop the CoA spells.
* Server settings used on the test realm that are NOT defaults: `ClasslessWildcard.CoA.ClassSpells = 1` (without it CoA class
  baseline passives are not granted and, for example, Necromancer minion capacity stays 2 so Raise: Abomination cannot be cast),
  `Esteria.Swap.Enable = 1` with `CharacterDatabase.WorkerThreads = 1` (character hot-swap).
* Client side: the swap sky archive (`Interface/Esteria/SwapSky*.tga`, generated by `client/Tools/EsteriaShell/build_swap_art.py`)
  must be packed into an archive; loose files under `Interface/Esteria` were not found by the client.
